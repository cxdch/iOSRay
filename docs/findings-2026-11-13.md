# Находки 13.11.2026

Проверено на OpenXRay `dev` @ `ddb78a5` (6.11.2026) и ветке TmLev `tmlev/shadow-of-chernobyl` @ `a6df2a2` (12.08.2026).

## Шейдеры: GLSL OpenXRay → MSL

286 GL-шейдеров (`res/gamedata/shaders/gl`, 199 `.ps` + 87 `.vs`), glslang 15.1 + SPIRV-Cross (master), MSL 2.1 для iOS.

| Пресет | Сконвертировано в MSL | Не собралось |
| --- | --- | --- |
| high (динамический свет R2) | **279 из 286** | 7: `fxaa.ps`, `gather.ps` — вспомогательные куски без `main`; 5 SSAO-вариантов — нужен свой набор define |
| low (`USE_R2_STATIC_SUN`) | 242 из 286 | 44: в основном `deffer_base_*` — несовпадение типов в ветке «статического солнца»; ветку для GL, похоже, никто не проверял |

- Ни один шейдер не упал на шаге SPIR-V → MSL: все проблемы — в GLSL-исходниках или наборе define.
- 14 вершинных шейдеров моделей собираются только со `SKIN_0..4` — движок так их и использует.
- Лимиты Metal не задеты: максимум 11 буферов, 11 текстур, 11 сэмплеров на шейдер.
- SPIRV-Cross делает из «свободных» uniform отдельные `constant`-буферы (`m_WVP [[buffer(0)]]`).
  Для движка нужно либо собирать их в один uniform-блок, либо строить таблицу «имя → слот» из reflection.
- 11 путей в `#include` записаны с другим регистром букв (`iostructs\p_aa_AA_combine.h`) —
  на iOS (регистрозависимая ФС) нужен поиск без учёта регистра.
- **Не проверено:** компиляция MSL драйвером Metal. Это и делает XRProbe на телефоне.

## Движок

- Рендер и игра уже линкуются статически в один исполняемый файл (`src/xr_3da/entry_point.cpp`) — `dlopen` для них на iOS не нужен.
- GL-специфичного кода немного: `xrRenderGL` + `xrRenderPC_GL` ≈ 9,8 тыс. строк. Остальное — общий слой `xrRender`/`xrRender_R2`
  (201 место с `USE_OGL`). Это и есть объём работы для `xrRender_Metal`.
- В апстриме появилась ветка `XR_PLATFORM_WEB` (114 мест): GLSL переписывается в ESSL 300 для WebGL 2.
  Запасной путь для ранней картинки на iPhone, пока нет Metal.
- SDL используется глубоко: 77 файлов, включая коды клавиш в `xrGame/ui`. **Решение: оставить SDL2 на iOS**
  (у SDL есть UIKit-бэкенд) как слой окна и событий, а Metal и сенсорный оверлей делать своими.
- Ветка TmLev для ТЧ свежая и большая (ПДА, задания, карта, анимации собак — август 2026),
  есть инструкция «ТЧ на Apple Silicon Mac» (`misc/macos/README.md`). Движок читает оригинальные
  зашифрованные `gamedata.db*` сам — распаковывать архивы не нужно.

## Первый запуск XRProbe на iPhone 7 Plus (A10, iOS 15.8.8, TrollStore)

- GPU: Apple A10, семейства Apple1–Apple3, **BC (DXT) не поддерживается** — текстуры игры придётся
  перекодировать в ASTC. `maxBufferLength` 750 МБ.
- Память (сборка с `increased-memory-limit`): при запуске доступно 2092 МБ из 2999 МБ физических,
  тест занял **1888 МБ** при запасе 150 МБ. Для сравнения нужен прогон `trollstore-base` без этого права.
- Шейдеры: драйвер Metal принял только **61 из 279**. 216 упали на одной и той же ошибке
  `address space mismatch`: SPIRV-Cross делал из каждого свободного uniform отдельный
  `constant`-буфер и передавал его во вспомогательную функцию, ждущую `thread`-ссылку.
  Ещё 2 (`deffer_detail_*`) упали на номере буфера >30: массив из 244 uniform занимал по слоту на элемент.
- Исправление: glslang запускается с `-V -R` — все свободные uniform собираются в один блок
  `gl_DefaultUniformBlock` в `[[buffer(0)]]`. После этого во всех 279 MSL-файлах ровно один буфер,
  и он передаётся в функции как `constant Block&`. Нужна повторная проверка на устройстве.
- Компиляция шейдера драйвером: 10–220 мс, весь набор — около 6 с на A10. В игре нужен кэш
  (`MTLBinaryArchive`) и прогрев на загрузке.

## Движок OpenXRay под iOS arm64 (первая сборка)

Кросс-сборка с Linux (clang 18 + lld + iPhoneOS SDK) и та же цепочка в CI на macOS.

- Зависимости собираются статикой скриптом `scripts/build_deps_ios.sh`: SDL2 2.30.9 (UIKit + Metal),
  OpenAL Soft 1.24.1 (бэкенд CoreAudio, NEON), Ogg/Vorbis, Theora (свой CMake, только декодер),
  LZO 2.10, LuaJIT (интерпретатор, `-DLUAJIT_DISABLE_JIT`).
- **Весь движок собрался и слинковался** в `xr_3da.app/xr_3da` (Mach-O arm64, iOS 15, ~65 МБ):
  xrCore, xrEngine, xrGame, xrPhysics, xrSound, xrScriptEngine, xrRender_GL и остальные.
- Понадобилось всего три правки (`patches/openxray/0001-ios-build.patch`):
  1. `LuaJIT-proj` не умеет кросс-компиляцию (определяет архитектуру хоста, жёстко прописан macOS SDK) —
     на iOS вместо него импортируется заранее собранная `libluajit.a`.
  2. `system("xdg-open …")` в xrGame недоступен на iOS → `SDL_OpenURL`.
  3. `install(TARGETS xr_3da)` для iOS-бандла.
- Запускать рано: нет точки входа через UIKit (`SDL_main`), путей к данным игры и рендера —
  GL-рендер на iOS работать не будет, это и есть следующая задача (Metal).
